# ADR-0014: Request pipeline, unit of work and server code generation

**Status:** proposed

## Context
T1 (07-transition) builds the platform skeleton every context will use. The
API contract is OpenAPI 3.1 with AIP custom methods (`/v1/x/{id}:cancel`).
Every request must run with the tenant and actor set on the database session
(ADR-0003), be idempotent when unsafe (ADR-0008), write its audit record in the
same transaction (ADR-0011) and emit events through the outbox (ADR-0007).

## Decision

**Code generation: ogen.** Server interfaces, request validation, JSON
encoding and the router are generated from `api/openapi.yaml` by
[ogen](https://github.com/ogen-go/ogen) into `api/gen` (checked in, excluded
from the coverage figure). Handlers implement the generated `Handler`
interface; contexts not yet built are served by the embedded
`UnimplementedHandler` (501). Every operation therefore exists in the server
with its validation from day one.

- `oapi-codegen` was rejected: its standard-library server registers
  `{id}:cancel` as a `ServeMux` pattern, which is invalid (a wildcard must be a
  whole segment), and its 3.1 support is partial.

**Pipeline, outermost first:**

| Step | Responsibility |
|---|---|
| Telemetry | Trace span (W3C `traceparent`), request id, structured log line, request metrics |
| Authentication | Bearer token verified against the issuer's keys (signature, issuer, audience, expiry); tenant from the token claim |
| Unit of work | One database transaction per request: `SET LOCAL ROLE erp_app`, `app.tenant_id`, `app.actor_id`; principal resolved and required active; safe methods run read-only |
| Idempotency | For `POST`/`PATCH`: key inserted in the same transaction; response buffered and stored with the key |
| Router (generated) | Route, decode and validate; unknown or malformed input answered as problem+json |
| Authorization | Operation's `x-permission` (read from the embedded contract) against the principal's current role permissions; `x-agent: false` refuses agents and services |
| Handler | Domain logic; adds audit entries and outbox events through the transaction in the context |

**Unit of work rules.**
- 2xx: buffered audit entries are written last (shortest hold of the tenant's
  chain-head lock), the idempotent response is stored, then commit, then the
  buffered response is sent.
- Business outcomes (404, 409, 410, 422): the business changes are rolled
  back to a savepoint taken after the idempotency insert; the answer is stored
  with the key and committed, so a retry gets the same answer.
- Request errors (400, 401, 403, 405, 412, 413, 428, 429) and 5xx: everything
  rolls back, including the key, so a corrected retry with the same key runs.
  (Storing a 428 for a missing `If-Match` would otherwise replay the 428 after
  the client fixed the header.)
- A concurrent request with the same key waits on the key's unique index for at
  most 5 s (`lock_timeout`), then gets 409 with `Retry-After`.
- Database errors are translated to stable problem codes; raw database
  messages never reach clients.

**Outbox relay.** A relay per cell publishes each context's outbox in order to
NATS JetStream (subject `erp.<cell>.<context>.<tenant>.<event>`, CloudEvents
binary mode, `Nats-Msg-Id` = event id for de-duplication). It runs as role
`erp_relay`, the only role that bypasses row-level security, with `SELECT` and
`UPDATE (published_at)` on outbox tables only. A transaction-scoped advisory
lock per context keeps one active publisher per context, which preserves order
per resource.

**Identity providers (T1).** Trusted issuers are configured per deployment
(issuer, audience, tenant claim). The per-tenant identity provider registry
(ADR-0010) arrives with the identity context in T2 and replaces the
configuration without changing the pipeline.

## Consequences
- A request holds one connection for its duration; long work goes to
  operations (ADR-0012), never into a request.
- The generated package is large (about 15 MB of Go) and slows a cold build by
  about 20 s; it is regenerated by `make generate` and checked in CI.
- Handlers never open transactions or touch idempotency, tenancy or audit
  plumbing directly; that is tested once, in the platform packages.
