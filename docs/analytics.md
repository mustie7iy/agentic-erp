# On-demand analytics

The platform has no catalogue of static reports and dashboards to build and
maintain. A person asks a question in plain language and the analytics agent
produces the report or dashboard on the spot: figures, charts, variance
tables and commentary, with every number traceable to a governed metric and a
query.

This replaces SAP embedded analytics, ALV reports, Analytics Cloud stories,
BW/4HANA and Datasphere queries, and Analysis for Office workbooks, together
with the consultant and BI-developer work of building and changing them.

## How a request is answered

1. **Ask**: for example, "monthly sales and analytics vs last year this time".
2. **Interpret**: the agent maps the words to governed metrics, periods and
   filters. When a term is ambiguous it uses the governed default and states
   the assumption, with one-click alternatives, instead of asking.
3. **Plan**: it chooses the comparisons, breakdowns and visuals that answer the question.
4. **Compute**: the semantic layer compiles semantic queries to SQL and the
   analytical store runs them. The agent never does the arithmetic and never
   writes raw SQL.
5. **Compose**: it assembles headline figures, charts, tables and commentary.
   A validator checks every figure in the commentary against the query results.
6. **Refine**: follow-ups ("why was May down?", "break North America down by
   product line") continue the same analysis. Good results can be saved,
   scheduled or shared.

## Worked example

**Request:** "Provide me monthly sales reports and analytics vs last year this time."

**Agent's reading:** net sales (billed revenue, the governed default for
"sales"), January to September 2026 against January to September 2025, all
regions, group currency USD. September is the last closed month. Offered
alternatives: order intake, fiscal quarters, by product line.

**Generated dashboard** (illustrative data):

- Headline figures: net sales year to date, latest month, gross margin, months above last year.
- Grouped bar chart of net sales by month, 2026 against 2025.
- Contribution to growth by region.
- Month-by-month variance table with totals.
- Commentary whose figures all come from the query results, plus suggested follow-ups.
- A "how these numbers were computed" panel:

```yaml
metric: net_sales
  source: billing documents, posted
  measure: sum(net_amount, group currency)
  excludes: intercompany, cancelled
  currency: USD at monthly average rate
  calendar: fiscal year = calendar year
```

```yaml
measures: [net_sales, gross_margin_pct]
by:       [fiscal_month, region]
where:    fiscal_year in (2025, 2026) and fiscal_month <= 9
security: requester's sales-org access
as_of:    2026-10-08T06:00Z   # data through 30 Sep close
```

## What people can ask for

| Capability | Description |
|---|---|
| Reports and dashboards | Any metric, period, comparison and breakdown the semantic layer knows, as tables, charts and headline figures |
| Drill-down and follow-ups | "Why?", "break it down by…", "show only EMEA" continue the same analysis |
| Saved and scheduled | A result kept as a living report that refreshes, or sent on a schedule |
| Shared | Shared with colleagues; each viewer sees only the data their access allows |
| Exports | Excel and PDF generated on request, with definitions attached |
| Proactive insights | The agent watches key metrics and raises anomalies in each person's workspace |
| Forecasting and what-if | Projections and scenarios over governed metrics (phase 9) |

## Guardrails

- **Numbers come from queries.** The model plans and explains; the analytical
  store computes. Commentary containing a figure not found in the results is rejected.
- **One definition per metric.** Metrics, dimensions and calendars are
  configuration as code, owned and approved by Finance and the business
  owners, and changed through the same tiered approval loop as other configuration.
- **Access follows the person.** Queries run with the requester's row-level
  security, so an answer never shows data the person couldn't open themselves.
- **Every answer shows its working.** Definitions, filters, data freshness and
  the query are one click away, and any result can be rerun exactly.
- **Bounded cost.** Query time and model spend per request are capped and
  attributed through the model gateway.

## Components

| Component | Choice |
|---|---|
| Semantic layer | Metric, dimension and calendar definitions as configuration as code; Go compiler from semantic queries to SQL |
| Analytical store | Postgres change data capture into Parquet, queried by DuckDB embedded in Go; ClickHouse when volumes require it |
| Analytics agent | Claude via the Anthropic Go SDK, with tools to list metrics, run semantic queries, build a dashboard spec and save or schedule results |
| Dashboard rendering | Declarative dashboard spec generated by the agent, rendered by a Go chart renderer (go-echarts) in the server-rendered UI |
| Exports | Excel via excelize; PDF rendered server-side in Go |
| Narrative check | Go validator that matches every figure in commentary to query results |
